# Efficiency-aware placement: a negative result

The per-node reporter publishes window-based tokens/joule and KV-cache hit-rate into `NodeState.status`, reimplementing the NVML energy read that inferscope's ADR-010 validated and scraping the vLLM series that inferscope's ADR-011 names; placement ranks them as strict lexicographic tie-breakers inside warmth classes (`EfficiencyAware` strategy). Design accepted in [ADR-0007](adr/0007-efficiency-aware-closed-loop-placement.md). Phase A done: `EfficiencyAware` comparator as a pure function with property-tested warmth dominance and fail-open absence semantics, status fields and CRDs in place. Phase B done: per-node reporter (same image, DaemonSet entrypoint, disjoint-ownership status merge-patches), strategy threaded through both natural decision points (initial planning and post-preemption replacement), opt-in Helm wiring with least-privilege RBAC. Falsification level 2 passed 5/5 on kind (`hack/rehearsal/adr0007-run.sh`): EA discriminates on kvCacheHitRate at equal warmth on both decision paths, and degrades to warmth-first when signals are absent. The first in-cluster run also surfaced (and fixed) a real schema/design mismatch — required status fields are incompatible with multi-writer merge-patch ownership. Phase B extended with the real signal source: `VllmScrape` (vLLM prefix-cache counters, inferscope ADR-011 schema) and an NVML sampler behind a build-feature plus runtime double gate, joined cross-source into `tokensPerJoule` on the same reporting round. Level-3 mechanism validated on 3x A10 (Lambda, k3s, one vLLM per node, [evidence](../hack/gpu-session/adr0007-ea-experiment/runs/20260723T175747)): NVML populates `NodeState.status` in vivo on all three nodes and the KV-cache scrape on the one that received traffic (the replay drove a single endpoint), `EfficiencyAware` and `WarmthFirst` diverge deterministically at both decision points, 8/8 reps clean with the operator log free of anything but two named benign classes. The primary hypothesis was open until phase C closed it, and the answer is negative. The level-3 run could not test it — the replay drove one fixed endpoint by design and nothing routed traffic to the service just placed, so both arms measured the same loaded node and the near-zero delta was determined before any GPU minute was spent (recorded as a post-run amendment in that [experiment design](../hack/gpu-session/adr0007-ea-experiment/DESIGN.md)). [Phase C](../hack/adr0008-phasec-experiment/DESIGN.md) built the missing path — placements publish what the planner ranked on, observations carry when they were measured, and a dispatcher sends the workload to the placed replica — then measured 8 reps on 3x A10: **EfficiencyAware 10.384 tokens/joule on the placed node against WarmthFirst 10.175, +2.05%, 95% CI [-2.5%, +6.6%], below the +3% threshold fixed before the run.** A negative result about EA under this workload, and one this design was entitled to draw: the strategies diverged deterministically, with EA choosing the better-tokens/joule node in 4 of 4 reps across both physical machines while WarmthFirst took the same node every time by list order. Two findings travel with it — the power cap makes a node *more* efficient per token rather than less, the opposite of what the design assumed, so the available margin was ~6% and a +3% threshold against it is a demanding test; and the pre-flight caught the reporter publishing 0.0 tokens/joule for an idle GPU, which would have handed both arms identical inputs and reproduced the level-3 null from the instrument.
